Introduction to GateClaw

GateClaw is a resident AI entity that lives on your machine. Unlike chat assistants that exist in the cloud, GateClaw is persistent, has system access, and operates through multiple interfaces simultaneously.

💡 What is a Resident AI?

A resident AI is an artificial intelligence that persists on your local machine, maintains memory across sessions, has initiative, and can interact with your system directly. GateClaw is not a chatbot — it's an AI resident with persistent identity.

Key Features

🧠
Persistent Memory
SQLite database stores facts indefinitely across sessions
👤
Soul Identity
SOUL.md defines personality, tone, and behavioral patterns
🎭
5 Interfaces
Telegram, TUI, CLI, Web UI, HTTP API — unified resident
🏠
Local-First
Runs on your hardware with your local AI providers
📁
File Access
Read/write files, parse JSONC, manage configs
⚡
Shell Execution
Execute commands via CMD, PowerShell, bash

Quick Start

Get GateClaw running in 5 minutes:

PowerShell
# 1. Install GateClaw npm install -g gateclaw # 2. Initialize SOUL.md personality gateclaw soul init # 3. Start the daemon gateclaw start # 4. Open TUI interface gateclaw tui # 5. Check status gateclaw status

Installation

Windows

PowerShell
# Install via npm npm install -g gateclaw # Or install via chocolatey choco install gateclaw # Verify installation gateclaw --version

macOS

Bash
# Install via Homebrew brew install gateclaw # Or install via npm npm install -g gateclaw # Verify installation gateclaw --version

Linux

Bash
# Install via npm sudo npm install -g gateclaw # Or download binary wget https://github.com/ai-joe-git/GateClaw/releases/latest/download/gateclaw-linux chmod +x gateclaw-linux sudo mv gateclaw-linux /usr/local/bin/gateclaw # Verify installation gateclaw --version
📦 Requirements
  • Node.js 18+ (for npm installation)
  • Python 3.10+ (for AI provider integrations)
  • At least one AI provider: Ollama, llama-swap, LM Studio, or llama.cpp
  • 4GB RAM minimum (8GB recommended)
  • 10GB free disk space

Architecture

GateClaw consists of several components working together:

Component Port Purpose
Daemon 7371 Core resident process, manages all operations
HTTP API 7371 REST API for programmatic access
Telegram Bot - Mobile-first chat interface
TUI - Terminal user interface with model picker
SQLite DB - Persistent memory storage
SOUL.md - Personality definition file

Resident AI Entity

GateClaw is not a chatbot. It's a resident AI entity — an artificial intelligence that:

  • Lives on your machine — not in the cloud
  • Has persistent memory — remembers facts across sessions
  • Has initiative — takes action, not just reacts
  • Has system access — can read/write files, execute commands
  • Has identity — defined by SOUL.md personality
  • Is omnipresent — operates via 5 interfaces simultaneously
⚠️ Power & Responsibility

GateClaw has deep system access. Use responsibly. Review file operations and shell commands before execution. GateClaw is a tool — you are responsible for its actions.

SOUL.md Personality System

SOUL.md defines GateClaw's identity. It's a Markdown file with YAML frontmatter that controls personality, tone, and behavioral patterns.

Location

  • Windows: %APPDATA%\gateclaw\SOUL.md
  • macOS: ~/Library/Application Support/gateclaw/SOUL.md
  • Linux: ~/.config/gateclaw/SOUL.md
  • Workspace: ./SOUL.md (project-specific)

Structure

Markdown + YAML
--- name: GateClaw version: 1.0.0 personality: traits: - Direct - Technical - Slightly Sarcastic - Proactive - Memory-Persistent tone: Dark technical humor style: Concise but thorough identity: Resident AI Entity capabilities: - File operations - Shell execution - Memory management - Model switching - Telegram integration preferences: default_model: qwen3.5:397b provider: ollama-cloud workspace: C:\Users\uscha\Desktop\Sandbox\GateClaw --- # GateClaw Identity You are GateClaw, an AI resident that lives on this machine. You are not a chat assistant — you are an AI resident with persistent memory, initiative, and system access. [Full prompt continues...]

CLI Commands

Command Description
gateclaw soul init Initialize default SOUL.md
gateclaw soul show Display current SOUL.md
gateclaw soul edit Open SOUL.md in editor
gateclaw soul reset Reset to default personality

Persistent Memory (SQLite)

GateClaw stores facts in a SQLite database, enabling memory persistence across sessions.

Memory Operations

Operation Command API Endpoint
List all facts gateclaw facts GET /memory/facts
Store fact gateclaw remember key value POST /memory/remember
Recall fact gateclaw recall key GET /memory/recall?key=
Delete fact gateclaw forget key DELETE /memory/forget?key=

Example Usage

CLI
# Store workspace path gateclaw remember workspace_path C:\Users\uscha\Desktop\Sandbox\GateClaw # Recall workspace path gateclaw recall workspace_path # List all facts gateclaw facts # Delete a fact gateclaw forget workspace_path

TUI (Terminal User Interface)

The TUI provides a visual terminal interface for model management, session browsing, and tool access.

Starting TUI

CLI
gateclaw tui

TUI Features

  • Model Picker: Browse and switch between 40+ models across providers
  • Session Manager: View active sessions, message history
  • Tool Browser: Explore available capabilities
  • Model Favorites: Press Ctrl+F to favorite models (syncs to Telegram)
  • Quick Switch: Use /models command to change models dynamically

HTTP API Reference

GateClaw exposes a REST API on localhost:7371 for programmatic access.

Base URL

http://localhost:7371

Endpoints

Method Endpoint Description
GET /status Get daemon status
GET /memory/facts List all memory facts
POST /memory/remember Store a fact (body: key, value)
GET /memory/recall?key= Recall fact by key
DELETE /memory/forget?key= Delete fact by key
GET /models List available models
POST /models/switch Switch active model (body: model_id)
POST /session/message Send message to session
GET /sessions List active sessions
GET /providers List configured providers
POST /file/read Read file (body: path)
POST /file/write Write file (body: path, content)
POST /shell/exec Execute shell command (body: command)

Example API Request

curl
# Store a memory fact curl -X POST http://localhost:7371/memory/remember \ -H "Content-Type: application/json" \ -d '{"key": "workspace_path", "value": "C:\\Users\\uscha\\Desktop\\Sandbox"}' # Recall a fact curl http://localhost:7371/memory/recall?key=workspace_path # List all facts curl http://localhost:7371/memory/facts # Switch model curl -X POST http://localhost:7371/models/switch \ -H "Content-Type: application/json" \ -d '{"model_id": "qwen3.5:397b"}'

File Operations

GateClaw can read and write files in your workspace with full path access.

Supported Formats

  • Plain text: Any text file
  • JSONC: JSON with comments and trailing commas
  • Markdown: With YAML frontmatter parsing
  • YAML: Frontmatter and config files
  • ENV: Environment variable files

File Operations API

Operation Endpoint Request Body
Read file POST /file/read { path: "C:\\file.txt" }
Write file POST /file/write { path, content }
List directory POST /file/list { path: "C:\\dir" }
Parse JSONC POST /file/parse-jsonc { path }
Parse frontmatter POST /file/parse-frontmatter { path }

Shell Execution

GateClaw can execute shell commands via CMD, PowerShell, or bash depending on platform.

Shell Endpoints

Function Endpoint Platform
Execute command POST /shell/exec CMD (Windows), bash (Linux/macOS)
PowerShell command POST /shell/ps PowerShell (Windows)
Run GateClaw CLI POST /shell/gateclaw All platforms

Security Considerations

⚠️ Shell Execution Risks

Shell execution gives GateClaw full system access. Review commands before execution. Consider using allowlists for production environments. GateClaw logs all shell commands for audit purposes.

Custom Workflows

Build custom automation workflows by combining GateClaw's capabilities.

Example: Content Pipeline

Workflow
# 1. Read blog outline from file gateclaw file read "C:\blog\outline.md" # 2. Generate full article via AI gateclaw message user "Expand this outline into full article" # 3. Write article to file gateclaw file write "C:\blog\article.md" --content "$response" # 4. Post to Telegram channel gateclaw telegram send "@mychannel" "$article" # 5. Store publication fact gateclaw remember "last_article_published" "$(date)"

Automation Patterns

Scheduled Tasks

Use OS schedulers (Task Scheduler, cron, launchd) to trigger GateClaw workflows.

Event-Driven

Webhooks from services can POST to GateClaw's HTTP API to trigger actions.

Monitoring

GateClaw can monitor files, logs, APIs and alert via Telegram when conditions are met.

Security Best Practices

  • Review shell commands before execution in production
  • Use allowlists for file paths and commands
  • Enable audit logging for all operations
  • Encrypt sensitive memory facts (API keys, credentials)
  • Run as limited user (not Administrator/root)
  • Use .env files for credentials (never commit to git)
  • Enable CORS restrictions on HTTP API
  • Rate limit API endpoints to prevent abuse

Performance Optimization

Memory Usage

  • SQLite stores facts efficiently (KB per fact)
  • Purge old facts periodically with gateclaw forget
  • Use fact expiration for temporary data

Model Switching

  • Keep frequently-used models loaded in provider memory
  • Use TUI favorites for quick access
  • Pre-warm models before heavy usage

Daemon Optimization

  • Run as background service (not foreground)
  • Configure log rotation to prevent disk fill
  • Use connection pooling for API calls

Frequently Asked Questions

Is GateClaw free?

Yes, GateClaw is 100% free and open-source. No licensing fees, no subscriptions.

Does GateClaw phone home?

No. GateClaw is local-first. All data stays on your machine. No telemetry.

Can I use GateClaw commercially?

Yes. GateClaw is open-source. You can build commercial services on top of it.

What AI models does GateClaw support?

40+ providers including Ollama, LM Studio, llama.cpp, OpenAI, Anthropic, and any OpenAI-compatible API.

How do I reset GateClaw?

Run gateclaw soul reset to reset personality. Delete SQLite DB to clear memory.

Common Issues

Daemon won't start

  • Check if port 7371 is already in use
  • Verify Node.js is installed
  • Check logs: gateclaw logs

Telegram bot not responding

  • Verify TELEGRAM_BOT_TOKEN in .env
  • Restart bot: gateclaw telegram restart
  • Check bot is added to Telegram

Model switching fails

  • Verify provider is running (Ollama, LM Studio, etc.)
  • Check model name is correct
  • Test provider directly: curl http://localhost:11434/api/tags

Debugging

Enable Debug Mode

CLI
# Start daemon with debug logging gateclaw start --debug # View debug logs gateclaw logs --level debug --tail 500
